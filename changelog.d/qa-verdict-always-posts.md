- QA role: a QA verdict (`Done:`, `Handoff:`, `Question:`) is never blocked by the three-comments-a-day cap, a near-duplicate edit, an owner-mention refusal or a plain-language hold; the hold reasons are logged and the verdict posts, so a run that reached a verdict no longer ends as "no verdict marker" (exit 65). `Answer:`, `Decision:` and unmarked comments stay capped.
- All roles: a comment that starts with a marker skips the server-side improve-readability rewrite, which was silently dropping the marker. It goes through the checked writer instead, which keeps the marker or posts the original text. This also keeps developer `Handoff:` markers readable for run outcomes.
- QA role: a QA verdict that links the developer's pull request no longer reads as "QA opened a pull request", so QA runs stop posting a PR hand-off comment (which used up the ticket's comment cap) and stop moving the ticket to review after the verdict moved it.
